# Object Authority Contract

> Status: v0.8-beta MVP contract. Object authority is human-managed, Git-backed, and file-based under the active `PKOS_DATA_ROOT`.

## Authority Paths

Object authority lives only in the data root:

```text
objects/fact/**
objects/claim/**
objects/skill/**
objects/creative/**
objects/deletions/YYYY-MM-DD.jsonl
```

The rebuildable object index is:

```text
runtime/objects/index.json
```

SQLite, Web state, Agent events, and runtime JSON are not object authority.

## Supported Types

Trusted knowledge track objects are `fact`, `skill`, and `claim`. They use the normal PKOS state machine and are eligible for Review/SRS onboarding.

`creative` remains an internal writing track. It uses its own lifecycle such as `draft`, `revised`, and `archived`; it is not default SRS material and is not public publishing output.

## Editable And Immutable Fields

Object type contracts are exposed through:

```text
GET /api/pkos/object-types
python -B -m tools.pkos object-types --json
```

The contract includes editable fields, required fields, status enum, field value types, SRS eligibility, immutable fields, supported supplementary sections, and the common object ID rule.

Object ID constraints are exposed as `objectId` on each type contract:

```json
{
  "minLength": 3,
  "maxLength": 64,
  "pattern": "^[a-z][a-z0-9_-]*(?:\\.[a-z0-9_-]+)+$",
  "humanReadablePattern": "Allowed / 允许: 3-64 ASCII chars; lowercase letters and numbers; dot, hyphen, or underscore separators; must start with the selected type prefix, such as fact.example.",
  "example": "fact.example",
  "prefixRequirement": "must_start_with_type_dot"
}
```

Web clients must read this contract instead of copying `maxLength` or regex rules into UI components. The Python authority remains the final validator.

The following are immutable for normal editing:

- `id`
- `type`
- `created_at`
- `srs`

The server manages:

- `updated_at`
- `fileRevisionSha256`
- `objectContentSha256`

Unknown existing fields must be preserved on update and may be shown read-only as Additional Fields. The MVP does not provide an arbitrary YAML editor.

Field contracts are type-specific. A Web client must not show or submit a field merely because another object type supports it:

- `fact`, `skill`, and `claim` use `source` and `anchors` as `string_list` fields.
- `creative` uses `tags` as a `string_list` field.
- `fact` does not expose `tags` in the v0.8-beta contract.
- Long text fields such as `content` are exposed as `multiline_string`; the authority writer serializes them through the shared YAML writer and then reloads the object before commit.

Submitting a field outside the active type contract fails with `invalid_object_field`. Submitting the wrong value type, such as a string where a `string_list` is required, fails with `schema_validation_failed`.

## Revision And Content Hash

`fileRevisionSha256` is SHA-256 over the raw object file bytes. It is the optimistic concurrency token required by update and delete.

`objectContentSha256` is the semantic Review/SRS hash. It excludes the `srs` projection and is used for `contentChangedSinceLastReview`.

These hashes must not be mixed. Any file byte change changes the revision; not every projection change should be treated as a human content change.

## Canonical Path Rules

Object file paths are derived only by the Python authority layer from object type and object id. API and CLI callers do not submit arbitrary file paths.

The authority layer rejects path traversal, absolute paths, drive paths, UNC paths, unsafe encoded path segments, type/id mismatches, and paths that resolve outside `objects/`.

## Create Transaction

Create requires:

- `confirmed: true`
- `requestId`
- clean Git data root
- valid type/status/schema
- non-existing object id
- non-tombstoned object id
- no client supplied `created_at`, `updated_at`, or `srs`

The server writes the object atomically, validates it, rebuilds object and Review/SRS projections, stages only the changed data-root files, commits with:

```text
object: create <objectId>
```

Idempotent replay with the same `requestId` and payload returns the previous result without another write or commit. A different payload for the same `requestId` fails with `idempotency_conflict`.

## Update Transaction

Update requires `baseRevision` equal to the current `fileRevisionSha256`.

The patch may change only editable fields. Unsubmitted fields and unknown existing fields are preserved. `updated_at` is generated by the server. Updating content does not reset SRS and does not create a review event; Review/SRS exposes `contentChangedSinceLastReview` instead.

The commit message is:

```text
object: update <objectId>
```

Stale edits fail with `object_revision_conflict`.

## Render Contract

Object render is centralized in `tools/object_flow/render.py` and surfaced through:

```text
GET /api/pkos/objects/:objectId/render
python -B -m tools.pkos object-render --object-id <objectId> --json
```

The body priority is:

```text
content > definition > explanation > notes > body > text
```

Render returns bounded structured output: `body`, `sections`, `metadata`, `fileRevisionSha256`, and `objectContentSha256`. Web and Review pages must not reimplement body-field probing.

## Delete Preflight

Delete preflight rescans current authority and returns blockers, warnings, review event count, tombstone state, and reference coverage.

Reference coverage includes object references, retired publish/blog references if present, task references, reminder references, digest references, and review history.

Blockers prevent delete. Warnings, such as existing review history, may allow delete but must be shown to the human. The MVP does not implement force delete or cascade delete.

## Hard Delete And Tombstone

Hard delete uses:

```text
POST /api/pkos/objects/:objectId/delete
python -B -m tools.pkos object-delete --object-id <objectId> ...
```

It requires:

- `confirmed: true`
- matching `typedObjectId`
- non-empty reason
- current `baseRevision`
- successful fresh preflight

The object file is removed, a deletion tombstone is appended, projections are rebuilt, and the data root is committed with:

```text
object: delete <objectId>
```

The tombstone records object id/type, file/content hashes, deletion time, actor, request id, reason hash, payload hash, and schema version. It must not copy title, summary, content, source, anchors, or full YAML.

Deleted object ids are not reusable in this MVP.

## Git And Rollback

Formal object mutation requires the active data root to be a clean Git repository. The core repository must not be committed when `PKOS_DATA_ROOT` points elsewhere.

Each transaction stages only the changed authority files for that operation. Runtime projections remain derived and ignored unless a private vault chooses otherwise.

Rollback is ordinary Git rollback in the data root:

```bash
git -C <PKOS_DATA_ROOT> log --oneline -n 5
git -C <PKOS_DATA_ROOT> revert <commit_hash>
python -B -m tools.pkos --data-root <PKOS_DATA_ROOT> object-rebuild --json
python -B -m tools.pkos --data-root <PKOS_DATA_ROOT> review-rebuild --json
```

## SRS Integration

Creating or deleting reviewable objects rebuilds Review/SRS projections. `fact`, `skill`, and `claim` enter onboarding according to the Review/SRS contract. `creative` is excluded.

Deleting an object does not delete review logs. Existing review history becomes orphaned until restored by Git or handled by a future human workflow.

## Agent And Privacy Boundary

Agent/LLM code must not autonomously create, update, delete, migrate, or trust objects. Object mutation is a human action through fixed APIs and Python authority code.

Audit summaries may contain object ids, operation names, lengths, hashes, revisions, blocker counts, and commit hashes. They must not contain full title, summary, content, source, anchors, delete reason, absolute paths, API keys, or secrets.

## Legacy Isolation

Old static site and old FastAPI routes remain quarantined. New object authority does not import `tools/server/**`, does not add editing to `site-private`, and does not restore public publishing or legacy review writeback.
